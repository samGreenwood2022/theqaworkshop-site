// the syllabus

What you'll learn — and why it matters

Everything is taught hands-on, in JavaScript or TypeScript, using your choice of Playwright or Cypress — the two most in-demand automation tools in the UK job market. It's 1-to-1, so we build the whole course around the tool that's right for you.

✓

Interacting with and verifying web elements

Locators, element attributes and assertions — the fundamentals every automated test is built on, explained without jargon.

✓

Page Object Model design pattern

The same architecture used by real engineering teams, keeping tests clean and maintainable as a framework grows. One of several best practices woven through everything built on this course, not a one-off lesson.

✓

Independent, reliable tests

Tests that run in any order, don't depend on each other, and don't mysteriously fail on Fridays. The difference between a test suite people trust and one they ignore.

✓

Git and GitHub, done properly

Creating and managing a repository, working with branches, and building the version-control habits every automation role expects.

✓

CI pipeline integration

Setting up GitHub Actions so a full test suite runs automatically on every change — the difference between "I can write tests" and "I can do DevOps-era testing".

✓

API testing for negative and edge-case scenarios

Negative testing done properly: using API calls to push the application into broken, unexpected and edge-case states, then verifying how the webpage actually handles them. Faster than clicking through the UI, and finds bugs that pure UI testing misses.

✓

Accessibility reporting with axe

Integrating the axe plugin to generate accessibility reports — an increasingly in-demand skill, and a genuinely good thing to be able to do.

✓

Visual regression testing

Catching unintended visual changes — layout shifts, broken styling, misplaced elements — that functional tests alone won't pick up.

✓

Cucumber, Gherkin and feature files

Plain-English test scenarios that connect testers, developers and business analysts.

✓

AI-assisted automation, throughout

Not a bolt-on module — tools like Claude Code and GitHub Copilot are used across the course, exactly as modern automation teams work. Covers generating, refactoring and debugging tests with AI, and reviewing what it produces with a tester's eye. Knowing when the AI is wrong is the skill that sets a good tester apart.

Common questions

Do I need to know how to code?

No. You'll be writing TypeScript or JavaScript by the end, but we start from zero and I explain every line. If you can write a test case, you can learn this.

Playwright or Cypress — which will I learn?

Your choice — the course is built around one tool, not a shallow tour of both. If you're not sure which to pick, we'll decide together in the free intro chat: if your workplace already uses one, that's usually the answer; if you're aiming at the open job market, I'll give you my honest take on demand for each. Either way, the concepts you learn — locators, page objects, independent tests, CI — transfer between them.

How are the sessions scheduled?

Entirely around you. Sessions are typically 1.5–2 hours, remote, at times that fit your work and life. Evenings and weekends are fine.

What if I need more (or less) than 18 hours?

18 hours is the typical total, but it flexes with your experience — that's the point of 1-to-1. We'll talk about where you're starting from in the free intro chat.

Do I need an AI tool?

We use AI throughout the course — it's part of how modern automation teams work, so it's part of how you'll learn. I recommend signing up for GitHub Copilot or, preferably, Claude Code before we start. Not sure which? We'll cover it in the free intro chat, and I'll help you get whichever you choose set up in session one.
